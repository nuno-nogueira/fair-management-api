# Fair Management Platform

## 📖 About the Project
This project follows a microservices architecture, by splitting up the system into independent services, each with clearly defined responsibilities. This approach allows to develop and maintain each service independently.

The platform is designed around two main types of users:

- Buyers - users can discover fairs, save favorite fairs, leave reviews, and create personal shopping notes;
- Vendors - users who can manage their presence at different fairs and provide information about their products.

## ✨ Features
- buyer and vendor user profiles;
- fair creation, editing, and searching;
- fair location and vendor information;
- product category management;
- favorite fairs and vendors;
- fair ratings and reviews;
- personal shopping notes;
- product and vendor associations;
- notifications when a fair is about to start;

## 🧩 Microservices

👤 Users Service

Responsible for user registration, authentication, and user-related information.

Users can have different roles, including:

- buyer;
- vendor.

🏪 Markets Service

Responsible for managing fairs and their associated information.

This service uses GraphQL.

⭐ Favorites Service

Allows users to save fairs and vendors as favorites.

A favorite contains the user and the target being favorited, which can be either a fair or a vendor.

⭐ Ratings Service

Allows buyers to leave ratings and feedback for fairs they have visited. Each fair can be rated in 1-5 scale.

📝 Notes Service

Provides users with personal shopping notes.

This service was implemented using Python and FastAPI.

🔔 Notifications Service

Responsible for managing notifications generated by the platform.

## 🛠️ Technologies
- MongoDB for data persistence;
- NGINX as an API Gateway;
- GraphQL to implement the markets/fairs service;
- Python + FastAPI to implement the notes service;
- Java & Spring to implement the favorites service;
- Service communication through REST APIs.

## 🚀 Getting Started

Setup instructions will depend on the individual services and their required runtimes/configuration.

### Clone the repository:

```
git clone https://github.com/nuno-nogueira/microservices-api.git
cd microservices-api
```

Each microservice is contained in its own directory and can be configured and executed independently.

### Build Docker images (one per service)

From the repository root, build each service image with:

```
docker build -t users-service:1.0 ./users-service
docker build -t markets-service:1.0 ./markets-service
docker build -t favorites-service:1.0 ./favorites-service
docker build -t ratings-service:1.0 ./ratings-service
docker build -t notes-service:1.0 ./notes-service
docker build -t notifications-service:1.0 ./notifications-service
```

### Start everything with Docker Compose

From the repository root:

```
docker compose up
```

### Stop Containers
Press CTRL + C in the terminal, then run:

```
docker compose down
```
